# Data Retention

This document defines how `privmotion` should handle input data, generated
artifacts, local outputs, and demo media. It complements
[PRIVACY_MODEL.md](PRIVACY_MODEL.md) and [THREAT_MODEL.md](THREAT_MODEL.md).

`privmotion` is a research prototype. Its default data-retention policy is
`no-raw-rgb`: raw visual input may be read for processing, but raw RGB frames
should not be written into the output directory by default.

Raw-RGB non-retention is a retention control, not HIPAA de-identification. The
HIPAA-oriented `hipaa-expert-aggregate` profile writes aggregate-only outputs
for Expert Determination review, but a qualified expert must still determine
and document whether re-identification risk is very small.

## Default Retention Policy

```text
retention = no-raw-rgb
```

The default policy means:

- Raw RGB frames are decoded and processed in memory.
- Raw RGB frames are discarded after processing.
- Raw input files are not copied into the output directory.
- The output directory stores reduced or anonymized motion artifacts.
- Generated artifacts are still sensitive and should be retained only as long
  as needed.

## Data Lifecycle

| Stage | Data handled | Default retention behavior |
| --- | --- | --- |
| Input selection | Image, MP4/video, frame directory, RGB-D/depth-like input | User/operator keeps source data outside generated output directories. |
| Frame ingest | Decoded raw RGB or grayscale arrays | In memory only; discarded after processing. |
| Segmentation | Masks and intermediate image arrays | Intermediate arrays are not retained unless a silhouette mode is requested. |
| Pose extraction | Keypoints, boxes, centroids, confidence values | Stored only when skeleton or feature output is requested. |
| Export | JSON reports, PGM masks, PGM depth surrogates, GIF/MP4 previews | Written to the selected output directory. |
| Validation | File names and output-tree scan results | Stored in `retention_report.json` when generated by the pipeline. |
| Benchmarking | Utility/privacy proxy metrics | Stored in `benchmark_report.json` when requested. |
| Dataset evaluation | Per-sample outputs and aggregate report | Stored under the dataset-evaluation output directory. |
| HIPAA aggregate processing | Aggregate counts, redacted metadata, de-identification support report | Person-level artifacts, paths, source names, and exact frame timestamps are not written. |

## What Should Not Be Retained

Do not commit or intentionally retain:

- Raw videos of identifiable people.
- Raw RGB image frames.
- Source frame dumps.
- Private or non-consented datasets.
- YOLO or other model weight downloads such as `*.pt`.
- Generated local output directories such as `out/`, `outputs/`, or
  `privmotion-output/`.
- Virtual environments, caches, build artifacts, or install metadata.

The repository `.gitignore` is configured to ignore common local outputs and
model weights, but contributors should still check `git status` before
committing.

## What May Be Retained

The following artifacts may be retained when they are needed for development,
benchmarking, or demonstration:

- `metadata.json`
- `skeletons.json`
- `features.json`
- `retention_report.json`
- `benchmark_report.json`
- `dataset_report.json`
- `aggregate_report.json`
- `deidentification_report.json`
- `access_policy.json`
- `audit_log.jsonl`
- `silhouettes/*.pgm`
- `depth_surrogates/*.pgm`
- anonymized `preview.gif` or `preview.mp4`

These artifacts are not raw RGB copies, but they can still leak identity through
motion, body shape, posture, labels, source names, or dataset composition. Treat
them as sensitive derived data.

For `hipaa-expert-aggregate` runs, retain only `metadata.json`,
`aggregate_report.json`, `deidentification_report.json`, and
`retention_report.json`. Do not add previews, skeletons, features, masks, depth
surrogates, or benchmark reports to that output bundle.

## Recommended Retention Windows

These are recommended defaults for local prototype use, not legal requirements:

| Data class | Recommended retention |
| --- | --- |
| Raw input media | Keep outside the repo; delete as soon as no longer needed. |
| Local processed outputs under `out/` | Delete after development or review is complete. |
| Benchmark reports | Keep only while comparing runs or documenting results. |
| Dataset evaluation outputs | Keep only for the active experiment; regenerate when possible. |
| Demo media under `assets/` | Keep only if reviewed for residual identity leakage. |
| Model weights | Keep locally only if needed; never commit. |

If a real organization or institution uses `privmotion`, its own data
governance policy should define the exact retention period.

## Output Directory Policy

Use a dedicated output directory for generated artifacts:

```bash
PYTHONPATH=src python -m privmotion.cli.process \
  --input examples/videoplayback.mp4 \
  --output out/demo \
  --mode skeleton,silhouette,depth-surrogate,features
```

Avoid writing outputs:

- Into the source input directory.
- Over raw media folders.
- Into shared public folders.
- Directly into `assets/` unless generating reviewed demo media.
- Into system directories or paths outside the project without a clear reason.

## Demo Media Policy

The `assets/` directory is intended for GitHub-facing demo media such as
anonymized GIF or MP4 previews.

Before adding demo media:

- Confirm the preview was generated from anonymized `privmotion` outputs.
- Confirm the original raw video is not added.
- Review the preview for residual identity leakage.
- Check that filenames, captions, and metadata do not identify a person or
  private collection site.
- Prefer synthetic or consented input sources.

## Validation Before Sharing

Run validation before sharing an output directory:

```bash
PYTHONPATH=src python -m privmotion.cli.validate \
  --output out/demo
```

Expected default result:

```text
policy=no-raw-rgb
passed=true
violations=0
```

Validation is a practical guardrail. It is not a complete forensic proof that
raw data was never saved elsewhere on the machine.

## Deletion Guidance

For local generated outputs:

```bash
rm -rf out/demo
```

For all ignored local generated outputs:

```bash
rm -rf out outputs privmotion-output
```

Before deleting, make sure no needed benchmark report, anonymized demo, or
experiment result is stored only in that directory.

## Restricted Retention Controls

Phase 5 implements opt-in encrypted kinematic feature records only. It writes
`features.json` with `encrypted_records`, `access_policy.json`, and
`audit_log.jsonl` when `--feature-encryption fernet` is selected.

Encrypted feature records remain derived sensitive data and should not be
treated as HIPAA de-identified solely because they are encrypted.

The default implementation still does not store raw RGB and does not provide a
decryption CLI. Any future feature that stores raw RGB, decrypts records, or
adds broader recoverable identity-bearing data should require:

- Explicit opt-in configuration.
- Clear unsafe/restricted labeling.
- Encryption and key-management design beyond environment-variable demo keys.
- Access-control policy enforcement.
- Audit logging for every recovery attempt.
- Consent-oriented validation.
- Tests proving the default path remains `no-raw-rgb`.

## Contributor Checklist

Before committing:

- Run `git status --short`.
- Confirm no raw video or raw frame data is staged.
- Confirm no `out/`, `outputs/`, `privmotion-output/`, cache, virtualenv, or
  model-weight files are staged.
- Run `privmotion-validate` on any output directory intended for sharing.
- Review generated previews and metadata for residual identity leakage.
- Keep sensitive experiment outputs local unless there is a clear reason to
  publish them.
